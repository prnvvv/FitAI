# API conventions

The interactive, always-current reference is generated by FastAPI: **`/docs`** (Swagger) and
**`/openapi.json`** on a running development server. In production they are disabled unless
`EXPOSE_API_DOCS=true`. This page records the conventions that the schema does not capture.

## Basics

- All application routes are under **`/api/v1`**. Unprefixed: `GET /health`, `GET /health/ready`,
  `GET /health/guardrails`, and `GET /v1/models` (an empty discovery stub for editor plugins; FitAI is not an
  OpenAI-compatible API).
- Every `/api/v1` route requires `Authorization: Bearer <Supabase access token>`. The user identity comes only
  from the verified token; a client-supplied user id is never trusted.
- Another user's resource returns `404`, not `403`, so existence is not revealed.

## Route groups

| Group | Prefix | Notes |
|---|---|---|
| Auth | `/auth` | `GET /me` |
| Chat | `/chat` | `POST`: `{ message (1–4000 chars), conversation_id? }` → `{ conversation_id, response, title, sources[], actions[], tool_events[] }` |
| Conversations | `/conversations` | CRUD; `GET /{id}/messages` is paginated |
| Profile | `/profile` | `GET`, `PUT` (replace), `PATCH` (partial) |
| Memory | `/memory` | facts, `/history`, `/pending` with `/confirm` and `/reject` |
| Documents | `/documents` | multipart upload, list, rename, `/retry`, delete |
| Plan | `/plan` | planned sessions, day summary, templates |
| Workouts | `/workouts` | logged sessions and sets |
| Progress | `/progress` | measurements, series, BMI, derived metrics, records |
| Exercises | `/exercises` | global library plus the user's custom exercises |
| Location | `/location` | geocode, reverse geocode |
| Activity | `/activity` | activity log |

## Pagination

List endpoints return `{ "items": [], "total": 0, "limit": 20, "offset": 0 }`. `limit` defaults to 20 and is
capped at 100 (a larger value is a `422`); `offset` starts at 0.

## Errors

Every error uses one envelope:

```json
{ "error": { "code": "RESOURCE_NOT_FOUND", "message": "Human-readable message.", "details": {}, "request_id": "…" } }
```

| Status | `error.code` |
|---|---|
| 401 | `UNAUTHENTICATED` |
| 403 | `PERMISSION_DENIED` |
| 404 | `RESOURCE_NOT_FOUND` |
| 409 | `CONFLICT` (duplicate or stale confirmation) |
| 413 | `PAYLOAD_TOO_LARGE` |
| 415 | `UNSUPPORTED_MEDIA_TYPE` |
| 422 | `VALIDATION_ERROR` |
| 429 | `RATE_LIMITED` (with `Retry-After`) |
| 500 | `INTERNAL_ERROR` (generic; details are logged server-side only) |
| 503 | `SERVICE_UNAVAILABLE` |

## Behaviours worth knowing

- **Documents.** PDF, DOCX, TXT and Markdown (plus images through OCR) by extension **and** file signature, up
  to `MAX_UPLOAD_SIZE_MB` (10). Uploading identical bytes twice returns the existing item (`200`,
  `X-Duplicate: true`). Status moves `pending` → `processing` → `indexed` (shown as *Ready*) or `failed`, with a
  short `failure_reason`; a readable file with no extractable text is `indexed` with a `note`, not a failure.
  Rows stuck `pending`/`processing` for over 30 minutes are failed at start-up with a retry hint.
- **Memory.** Current facts live in `memories` (at most one active row per user and key); every change appends to
  `memory_history` in the same transaction. Proposals do not change memory until confirmed; deletes are soft.
  Deleting a conversation never touches profile, memory, measurements or workouts.
- **Progress.** Measurements are append-only; units are validated per type (`kg`/`lb`, `cm`/`in`, `%`).
- **Rate limits.** Per client: chat, uploads, location and writes are limited more tightly than reads; repeated
  failed authentication is throttled. See `RATE_LIMIT_*` in [`backend/.env.example`](../backend/.env.example).
